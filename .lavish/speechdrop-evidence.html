3. Rust Security Boundary

The web side never passes a URL - only {roomCode, fileName, contentType, contentBase64}. The Rust command validates and builds the URL from a fixed base.

// src-tauri/src/commands/speechdrop.rs (Rust unit tests all pass)

validate_room_code("ABC123") // ✓ ok - 6-char alnum

validate_room_code("../etc") // ✗ Err - path injection rejected

is_allowed_mime("text/rtf") // ✓ accepted

is_allowed_mime("text/html") // ✗ blocked

// Two-request CSRF flow: GET /{room}/index → POST /{room}/upload

// Host-locked to https://speechdrop.net

4. RTF Formatting Preservation

SpeechDrop rejects text/html but accepts text/rtf. The target converts the payload's HTML to RTF via htmlToRtf - preserving bold, underline, highlight, and headings.

Input HTML (payload.html)

<h1>Affirmative</h1>
<p><strong>Smith 24</strong> <u>the evidence</u></p>
<p><mark>highlighted text</mark></p>

Output RTF (uploaded as .rtf)

{\rtf1\ansi ...
{\colortbl;\red255\green255\blue0;}
\b Affirmative\b0\par
{\b Smith 24} {\ul the evidence}\par
{\highlight1 highlighted text}\par}
