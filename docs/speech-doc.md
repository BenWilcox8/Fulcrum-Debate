# Speech doc, split-screen docking, and speech pipelines

The Speech Doc editor + model, the split-screen dock on the round/block-file screens, and the two content pipelines that push into the active speech doc (Send Flow, drag-a-card). The ToC bulk-send pipeline lives in `docs/toc.md`.

## Speech doc (`src/speech-doc/`)

The Speech Doc editor, its document model, and the split-screen docking layout - the whole **Speech Doc Editor & Split-Screen Docking** PRD (slice 1/2 = editor + model, below; slice 2/2 = docking, see "Split-screen docking"). The pipelines that push content in - Send Flow, ToC "build a speech", drag-a-card - are separate PRDs; Shorthand is separate. Re-exported from `src/speech-doc`.

- **A speech doc *is* a `speech-doc` document, mirroring the round seam.** Every speech doc is one `speech-doc` {@link src/documents | document}, so its stable id *is* that document's id; its rich text lives in the fixed top-level `Y.XmlFragment` `body` (`SPEECH_DOC_BODY_FRAGMENT` in `speech-doc.ts`, a sibling name to the block-file/RFD bodies - see the Fragment convention table). It is edited through the shared {@link DocumentEditor} + plain `editorPreset()` (bold, highlight, font size, headings - so bold taglines etc. work), so content autosaves and reloads through the identical Yjs + y-indexeddb path with **no bespoke storage**. Unlike the block file (a workspace singleton), a debater keeps *many* speech docs, so `useSpeechDocs()` mirrors `useRounds` (list/create/remove over the `speech-doc` kind), not the singleton find-or-create. No new infrastructure: the document registry already indexes by kind.
- **The active speech doc is the track's key shared surface (`active-speech-doc.ts`).** The content-pipeline PRDs all push into *the active speech doc*, so this module names it at the **model level**, decoupled from routing/editor/docking: a React-free `ActiveSpeechDocStore` (`createActiveSpeechDocStore()`) holding one **document id** (`getActiveId()` / `setActiveId(id | null)` / `subscribe`). A pipeline resolves its target by `getActiveId()` then opening that document through the shared service - it never needs to know how the id was chosen. This is **transient session state, not persisted document content** (a moment-to-moment pointer, deliberately kept out of the Yjs types so it never syncs/conflicts; a reload starts with none active). Pin the identify/set/observe contract when extending it.
- **React distribution mirrors the preference store.** `ActiveSpeechDocProvider` owns one app-lifetime store (or adopts one via the `store` prop for tests); `App` wraps the router in it alongside the other in-memory providers (boot-path safe). `useActiveSpeechDoc()` reads `{ activeId, setActiveId }` reactively via the store's own `subscribe` seam through `useSyncExternalStore` (never a second event system); `useActiveSpeechDocStore()` hands back the raw store for imperative use. Both are **provider-tolerant** (fall back to a private store, like the formatting/tools readers) so a bare editor/subtree still renders.
- **`SpeechDocEditor` marks its doc active on mount.** The editor component binds the shared surface to the doc's `body` and, given a `docId`, calls `setActiveId(docId)` on mount - so the speech doc a debater is editing is the one pipelines target (this is the seam the split-screen dock will reuse when it hosts the editor beside the flow). Paints its container synchronously with a `null` handle (local-first boot); the editable view mounts once the local load resolves.
- **The `.speech-doc-body` surface owns its own block typography (`src/index.css`), because the content is *appended*, not typed.** Tailwind's preflight resets paragraph margins to 0 and strips heading typography, so a speech doc filled by Send Flow / ToC bulk-send (many stacked paragraphs, plus preserved Auto-Speech section headers) rendered as one undifferentiated wall with headers indistinguishable from body text while the bold tagline below outranked them (UI audit V6/V7). The surface therefore carries scoped rules (mirroring `.block-file-editor`): `.speech-doc-body .ProseMirror > * + *` gets a `margin-top` so each appended argument reads as its own unit, and `.speech-doc-body .ProseMirror :is(h1..h6)` gets bold, sized, top-margined heading typography so a preserved section header outranks the tagline and opens its section (the header's top margin doubles as the visual boundary between distinct sends). Keep this scoped to `.speech-doc-body` (like the block-file `.block-file-editor` heading rules) so it never leaks onto other surfaces. Note the *plain-text* export form already separates blocks with `\n\n` (`doc.textBetween`), so the blob was an on-screen-editor-only problem - a CSS fix, no document-model change.
- **Routed surface (standalone, still shipped).** `/speeches` (`SpeechDocsScreen`, list + New), `/speeches/new` (`NewSpeechDocScreen`, create-and-redirect like `NewRoundScreen`), `/speeches/:speechDocId` (`SpeechDocScreen`, opens the doc + renders `SpeechDocEditor` + not-found guard). Linked from `RootLayout`'s primary nav ("Speeches"). This is the full-screen "edit one speech in isolation" route; the *docked* editor (below) is the same `SpeechDocEditor` beside the flow.
- **Tests:** `speech-doc.test.ts` (`fake-indexeddb`, real handle) pins the kind + fixed `body` fragment and the highest seam - a real shared-editor close/reopen round-trip proving a **bold** tagline autosaves and reloads intact (+ empty-on-fresh, two-doc isolation). `active-speech-doc.test.ts` drives the pure store (identify/set/clear/subscribe/unsubscribe/no-fire-on-unchanged/isolation). `active-speech-doc.react.test.tsx` covers the reactive hook, write-back, provider sharing, and no-provider fallback. `SpeechDocEditor.test.tsx` covers synchronous paint, the mounted surface, marks-active-on-mount, and rich text landing in `body`. `speech-doc.integration.test.tsx` drives the routed shell (create → editor mounts; reopen a fresh provider over the same IndexedDB restores bold text; **opening a speech doc makes it identifiable as the active speech doc** by id; not-found; index listing).


### Split-screen docking (`src/speech-doc/dock/`)

Slice 2/2 of the PRD: the Speech Doc editor docks alongside the flow sheet on the **round screen** (`RoundScreen`), so a debater flows and drafts/reads a speech in one view. `SpeechDockLayout` is the one component a screen mounts; re-exported from `src/speech-doc` (and `src/speech-doc/dock`).

- **The dock is view chrome, persisted in `localStorage` (not Yjs).** The layout preference - dock **edge** (`side` = vertical split on the right, `bottom` = horizontal split below) plus a fractional **size per edge** - is per-machine reading chrome like window geometry, so it persists locally, **not** in the shared document types (which would sync/conflict). `dock-layout.ts` is the pure model (`DockLayout = { position, sizes: Record<DockPosition, number> }`, `clampDockSize`, `dockSizeFor(layout, position?)` for the current edge's clamped size, `normalizeDockLayout` for corrupt-value tolerance **and legacy single-`size` migration**, `MIN/MAX_DOCK_SIZE` = 0.2/0.8); `dock-layout-storage.ts` reads/writes it under `DOCK_LAYOUT_STORAGE_KEY = "fulcrum:dock-layout"` (best-effort writes swallowed, malformed reads degrade to default - the window-geometry discipline); `useDockLayout(storage?)` seeds **synchronously** from storage (no async gate, upholds local-first boot) and writes back on every `setPosition`/`setSize`. Pass an explicit `null` storage to disable persistence (pure in-memory); omit for real `localStorage`; pass a stub in tests.
  - **The dock fraction is remembered per orientation, with a distinct default per edge (audit finding V2).** `DEFAULT_DOCK_SIZES = { side: 0.4, bottom: 0.3 }` - 40% of the *width* is a comfortable side pane, but 40% of the *height* left the flow ~one contention tall with the RFD crushed, so **bottom defaults lower (0.3)** to keep the flow tall. `setSize` writes onto `sizes[layout.position]` only, and toggling the edge switches to that edge's remembered (or default) fraction rather than carrying the other edge's fraction across - a side width and a bottom height are independent preferences. `SpeechDockLayout` passes `dockSizeFor(layout)` (the current edge's size) to `SplitDock`. A pre-per-edge stored `{ position, size }` migrates by applying `size` to its stored edge and defaulting the other (`normalizeDockLayout`). The V2 fix pairs this with an **RFD floor**: `RfdSection`'s `<section>` carries `shrink-0` so the Reason-For-Decision region holds its ~heading+`min-h-16` height instead of collapsing to a ~60px sliver when the flow panel is short (the internally-panning canvas absorbs the squeeze instead).
  - **`SpeechDock`'s header wraps at narrow widths (audit finding V3).** In the 1024px three-pane block-file layout the dock pane is narrow *and* `overflow-hidden`, so the speech `<select>`'s intrinsic width used to push the Side/Bottom toggle + ✕ close off-screen (only "Side" showed). The header top row is `flex-wrap` with a **shrinkable** left group (`min-w-0 flex-1` on the group and the select, so the select truncates) and a **`shrink-0`** right control group, so the toggle and close stay reachable - wrapping to a second line before they would ever clip.
- **`SplitDock` is the generic resizable two-pane split.** Primary (flow) fills the remaining space; secondary (dock) takes `size` on the chosen edge. The divider is a real `role="separator"` with `aria-valuenow/min/max` and **arrow-key** resize, plus a pointer-drag using pointer *capture* (so a drag tracks past the divider). The drag→fraction math is the pure `dockSizeFromPointer(rect, position, x, y)` in `split-drag.ts` (dock sits on the far edge, so its fraction = `(containerFar - pointer)/extent`, clamped) - **unit-tested without a browser** because jsdom measures nothing (getBoundingClientRect is all zeros), the same reality the flow drag/edge tests hit. Both panes are `min-w-0 min-h-0` so the flow's XYFlow canvas measures a definite size and reflows on resize.
- **`SpeechDock` is the docked pane: editor + chrome that indicates the active speech.** It opens the {@link useActiveSpeechDoc | active speech doc} via `useDocument(activeId)` and renders `SpeechDocEditor`. Its header is the **active-doc indication**: a labelled `<select aria-label="Active speech doc">` shows/switches which speech is docked (choosing one calls `setActiveId`, which the editor also re-affirms on mount), plus a live `data-testid="active-speech-doc-indicator"` line ("Active speech: {title}" / "No active speech"). It also holds the side/bottom position toggle and a collapse (✕) control.
  - **Gotcha - the docked editor needs a *definite-height* parent, not `min-h-full`.** `SpeechDocEditor`'s inner box (`.speech-doc-body`) fills via `min-height:100%`, which only resolves against an ancestor whose height is definite. The standalone route gets that from `flex-1`; the **dock passes `h-full`** on `SpeechDocEditor` (a plain `min-h-full` there collapses the box to its ~1-line content height, floating it in an empty pane). Additionally, `.speech-doc-body` is a `display:flex` column with the `.ProseMirror` at `flex:1` (in `src/index.css`) so the editing surface fills the padded box and the whole area is a caret target - and that block also drops the contenteditable's default focus ring (`:focus { outline:none }`; the container's `focus-within` accent border + ring (`focus-within:border-aff-strong focus-within:ring-2 focus-within:ring-aff/40`) are the focus affordance), placed *before* the `.is-card-drop-target` rules so the drag drop-outline still wins.
- **`SpeechDockLayout` composes it and owns the collapse state.** Dock edge + size come from `useDockLayout` (persisted); whether the dock is **open** is session state (a debater collapses it to reclaim the full flow), deliberately *not* persisted - mirroring the flow's transient collapse view-state. Collapsed → the flow gets full space plus a slim right/bottom-edge **rail** whose "Open speech dock" button re-expands it.
  - **An empty dock never starves the flow (audit divergence D2).** With **no active speech doc**, the split would show only a "select a speech" placeholder while consuming the ~40% `size`, squeezing the flow columns for no benefit (state 002 in the audit: 5 columns crushed to ~2.5). So `SpeechDockLayout` reads `useActiveSpeechDoc` and starts **open only when a speech is already active** (`activeId != null && !isNarrowViewport()`) - otherwise it starts as the slim rail, giving the flow the full width. It **auto-expands to the split the moment `activeId` transitions null→non-null** (a `useEffect` keyed on that edge), whether the debater picks a speech from the rail's dock or a pipeline (Send Flow, ToC bulk-send) sets one active. A manual close (✕) returns to the rail without re-opening (the unchanged `activeId` never re-fires the auto-open). Both `RoundScreen` and `BlockFileScreen` mount it, so **both** screens now start collapsed until a speech is docked - a laptop-width E2E must click "Open speech dock" (`RoundHarness.openSpeechDock()`) before using the dock's active-speech `<combobox>` (this used to be narrow-only).
  - **Narrow-viewport default (responsive).** The initial `open` state is `!isNarrowViewport()`: **open by default on roomy viewports, collapsed by default below `NARROW_DOCK_BREAKPOINT` (1100px)** where a 40%-width side split would starve the flow (a 5-column flow on a 1024px screen compressed so hard the timer widget overlapped its columns). `isNarrowViewport()` reads `window.matchMedia('(max-width: 1099px)')` once, **guarded** so a non-browser env (jsdom, where `matchMedia` is absent) resolves to not-narrow → open - preserving the open-by-default behaviour the dock unit tests assert. It is the *initial default* only (the dock is always openable via the affordance); it does not auto-collapse on live resize. `SpeechDockLayout.test.tsx` stubs `window.matchMedia` to prove both the narrow-collapsed and roomy-open defaults. This applies on **both** the round screen and `BlockFileScreen` (both mount `SpeechDockLayout`), so a narrow-width E2E must click "Open speech dock" before using the dock's active-speech `<combobox>`.
- **Flowing stays fully usable while docked, and the timer coexists.** `RoundScreen` wraps its flow container (holding `FlowSheetPanel`, which carries the floating `TimerWidget` in its `overlay` slot) as `SplitDock`'s `primary`, so the flow keeps every interaction and the timers overlay the *flow canvas only*, never the dock, the controls strip, or the RFD. Browser-verified: both positions render, resize persists across reload, active-doc switching works, flow + RFD + timers all render alongside the dock.
- **Tests:** `dock-layout.test.ts` (pure model: clamp, normalize, defaults), `dock-layout-storage.test.ts` (round-trip via a stub Storage, default-on-missing/malformed, best-effort/null-storage), `split-drag.test.ts` (`dockSizeFromPointer` side/bottom/offset/clamp/zero-extent), `useDockLayout.test.tsx` (synchronous seed, persist-on-change, clamp, **survives-remount = reload**), `SplitDock.test.tsx` (both panes, side/bottom layout + aria, arrow-key resize, clamp, ignore non-arrows), `SpeechDock.test.tsx` (real `DocumentsProvider`: active indicator, select switches active + indicator, position toggle, collapse, editor mounts), `SpeechDockLayout.test.tsx` (both positions render, persisted-position load, position switch persists, **resize persists across remount**, collapse-to-full-flow + reopen, **empty-dock starts as rail - D2**, auto-expand-on-active, narrow-viewport-no-auto-expand).


## Send Flow -> Speech Doc pipeline (`src/flow/send-to-speech.ts` + `src/flow/canvas/`)

The **Send Flow** PRD: a debater Shift+Click multi-selects flow arguments (contentions and/or subpoints) and presses **Ctrl/Cmd+Enter** to append their content onto the end of the {@link ../speech-doc/active-speech-doc | active speech doc}, non-destructively. It reuses the active-speech-doc contract (PR #83) as the target and touches neither the argument-row transitions nor shorthand expansion. Model re-exported from `src/flow`; the selection/gesture/control from `src/flow/canvas`.

- **The append core (`send-to-speech.ts`, model-layer, Yjs-level).** `appendFlowNodesToSpeechDoc(flowHandle, speechHandle, nodeIds, bodyFragmentName?)` reads each selected container's own content fragment (`contention:<id>` / `subpoint:<id>`), **deep-clones every non-empty `<paragraph>` element** (Yjs `clone()`, mark-preserving + doc-agnostic, exactly like the cross-apply copy), and pushes the clones onto the speech doc body fragment (`SPEECH_DOC_BODY_FRAGMENT`) in **one transaction**. Append order is the flow's own reading order (columns, then contentions top-to-bottom, then their subpoints), regardless of selection order; ids that no longer resolve are skipped. Returns `{ nodeCount, paragraphCount }`. **Why flatten to paragraphs:** a flow box stores `argument > response > paragraph` but a speech body is plain `block+` with no `argument`/`response` node types, so only the shared `paragraph` type is extracted. Rich Auto-Speech reshaping is a **separate PRD, deliberately out of scope** - this is a faithful append. **It works at the Yjs level (not via an editor) on purpose:** collapsed containers mount no editor, so the pipeline must read fragments directly. **Non-destructive by construction:** the flow side is read-only; every write lands in the speech doc's own `Y.Doc`, so it persists + reloads like any speech-doc edit. **Gotcha - building detached Yjs XML:** use `applyDelta` + `insert` (never `.push` or attributed `.insert` on an *unintegrated* `Y.XmlText`/`Y.XmlElement`), else Yjs logs `Invalid access: Add Yjs type to a document before reading data` (the `.push`/format path reads `.length`/`.doc`). The migrate helper and the send tests follow this.
- **The selection (`useFlowSelection.ts` + `FlowSheetContext.selection`).** A transient `FlowSelectionState` (`selectedNodeIds`/`count`/`isSelected`/`toggle`/`clear`) owned by `FlowSheetProvider`, alongside the active-column and collapse state - **never persisted** (a send gesture, not a case property; a reload starts empty, and it never enters the Yjs types). `ContentionNode` and `SubpointNode` toggle their own id on **Shift+Click**, handled on `onMouseDownCapture` (so it wins over XYFlow's drag-start and the editor's caret/text-selection) with the follow-up click swallowed on `onClickCapture` (so the header's collapse toggle never fires for the same gesture). Selected containers carry `data-selected` and a `ring-2` treatment (dark ring on contentions, light ring on the dark subpoints). Shift+Click again deselects.
- **The gesture + affordance (`SendToSpeechControl.tsx`).** In the panel's toolbar strip beside the collapse button: a **Send to speech (N)** button (enabled once selection is non-empty) plus the document-wide **Ctrl/Cmd+Enter** hotkey - both call the same send. The hotkey deliberately uses **Ctrl/Cmd+Enter, never plain Enter/Shift+Enter**, so it never collides with the argument-row transitions or shorthand expansion those keys drive; it only acts on a non-empty selection (else it passes through) and `preventDefault`s when it acts. On success it clears the selection and shows a `role="status" aria-live` line ("Sent N argument(s) to your speech.").
- **No-active-doc = deliberate reversible no-op (tested).** When no speech doc is active, sending mutates nothing and surfaces a subtle inline affordance ("No active speech doc - open or select a speech to send into.") with the **selection preserved** so the debater can pick a target (via the dock's active-speech `<select>`) and retry. Auto-creating a doc from a chord was rejected: it would spawn stray docs and silently choose a target. **Provider-tolerance:** the control reads the `DocumentService` via a local `useOptionalDocumentService` (reads `DocumentsContext` directly -> `null` outside a provider, like the dashboard resume reader) and the active id via the provider-tolerant `useActiveSpeechDoc`, so the bare-`FlowSheetPanel` canvas tests (no `DocumentsProvider`) still render. It opens the target through `service.open(activeId)` (the service's cached handle - the same one the dock may already have open).
- **Tests:** `send-to-speech.test.ts` (`fake-indexeddb`, real flow + speech handles) is the highest seam - multi-select appended in flow order, selection filtering, nested subpoints, **mark preservation**, **flow untouched**, **persist across a speech-doc close/reopen**, multi-paragraph/empty-skip, and the empty/no-text no-ops. `useFlowSelection.test.tsx` covers toggle/deselect/multi-select/clear/stable-snapshot. `SendToSpeechControl.test.tsx` (real `DocumentsProvider` + `ActiveSpeechDocProvider`) covers disabled-until-selected, send-on-click + selection-clears + flow-intact, the Ctrl/Cmd+Enter hotkey, and the no-active affordance with preserved selection. The real Shift+Click / XYFlow gesture + Cmd+Enter send was **browser-verified in Chrome** (jsdom can't drive XYFlow), including the no-active affordance and the append landing in the dock's active speech.


## Drag a card into the Speech Doc (`src/speech-doc/card-drag.ts` + `card-drop.ts` + `card-drag-transfer.ts`)

The **Speech Doc Card Pipelines** PRD (drag track): a debater drags an individual block-file card by its grip **directly into the docked speech doc**, and it lands - COPIED, Auto-Speech-formatted, *with its argument-section heading* - at the precise drop position (not a bottom-append). It reuses the {@link ../speech.transformToSpeech | Auto Speech engine} and the {@link ./active-speech-doc | active-speech-doc contract} (PR #83); the block file is never mutated. All three modules re-exported from `src/speech-doc`. (Distinct from the **Send Flow** pipeline above, which appends *flow* content; and from the parallel ToC bulk-send track.)

- **Why the pipeline lives in `src/speech-doc`, not `src/blockfile`.** The drag source consumes both the block-file card APIs *and* the speech engine; the block file is the lower-level module and must not depend on speech. So both halves sit in `speech-doc` (which already depends on `blockfile` + `speech`) - **no dependency cycle**, and `blockfile/index` stays speech-free. `BlockFileScreen` (a top-level screen, free to compose features) imports the drag extension from `src/speech-doc/card-drag`.
- **The wire format (`card-drag-transfer.ts`) is a tiny, dependency-free seam.** It owns only the custom MIME `CARD_SPEECH_DRAG_MIME = "application/x-fulcrum-card-speech"` and `writeCardSpeechBlocks`/`readCardSpeechBlocks`/`hasCardSpeechDrag` over a `DataTransfer`. Both halves import it *without importing each other*. **The engine runs on the DRAG side** (which has the card node types) and the speech-ready block-level document-JSON travels on the drag - so the drop side is fully schema-agnostic (it inserts plain paragraph/heading/text+bold JSON, all present in the speech-doc preset). `hasCardSpeechDrag` reads `DataTransfer.types` (not `getData`, which browsers blank during `dragover`) so the drop target can decide to accept during `dragover`.
- **Drag source (`card-drag.ts`, `CardSpeechDrag` extension on the block-file editor).** A ProseMirror plugin renders a per-card **drag handle** as a view-only **widget decoration** at `cardPos+1` (a `⠿` grip, `draggable`, `contenteditable=false`) - no schema/document change. The handle's own `dragstart` listener (closed over `getPos`, so it reads the card's *live* position) calls `buildCardSpeechDragData(doc, pos, options?)` and writes the result, then `stopPropagation()`s so ProseMirror's internal node-drag never overwrites the payload (this is a pure external HTML5 drag). `buildCardSpeechDragData` is **pure** (reads the doc only): it `cardAt`-locates the card, finds the enclosing argument-section heading (nearest preceding level-`BLOCK_SECTION_HEADING_LEVEL` heading **scoped to the card's own side**, so a neg card never picks up an aff heading), wraps `[heading?, card]` under a throwaway `doc.type.create(null, ...)` (the `create`-not-`createChecked` pattern the Auto Speech clipboard tool uses), and runs `transformToSpeech`. Returns `null` for a non-card pos or an empty card (→ the drag carries nothing). CSS (`src/index.css`): `[data-card]` is `position:relative` and the handle is absolutely placed just left of the card, revealed on hover.
- **Drop target (`card-drop.ts`, `SpeechCardDrop` extension on the speech-doc editor).** A plugin whose `handleDOMEvents` (`dragover`/`dragleave`/`dragend`/`drop`) act **only** on a card-speech drag (else return `false`, leaving normal handling untouched). `dragover` `preventDefault`s + sets `dropEffect="copy"` (the copy cursor) and moves a live **drop indicator** (a horizontal-line widget decoration) to the resolved boundary, plus an `is-card-drop-target` class on the editable (CSS highlight + `cursor:copy`). `drop` inserts the payload's blocks. **Precise placement = resolve then snap:** `resolveSpeechDropPos(view, coords)` = `view.posAtCoords` then `snapDropPos(doc, pos)` - a **pure** function rounding to the nearest top-level block boundary (before the block if the pointer is in its top half, after otherwise), so block content never splits a paragraph. `insertSpeechBlocksAt(view, blocks, rawPos)` snaps again (idempotent) and inserts, returning the range.
- **Co-location: `BlockFileScreen` docks the speech editor** (wraps its editor column in `SpeechDockLayout`) so the card (drag source) and the active speech doc (drop target) are on one screen. **Gotcha this surfaced:** the dock adds a *second* `list()` consumer to the screen, so `blockfile-workspace/workspace.test.tsx`'s "retries and recovers" test could no longer key its transient failure to a `list()` **call count** (effects run child-first, so the dock's `useSpeechDocs` reads the registry *before* `useBlockFile`) - it now fails every `list` until a `recovered` flag is flipped before the retry click. `SpeechDocEditor` gained the `SpeechCardDrop` extension via a module-level `SPEECH_DOC_PRESET` (stable ref per the `useDocumentEditor` contract), so the drop works wherever the editor mounts (the dock *and* the standalone `/speeches/:id` route).
- **Testing reality (mirrors the flow-DnD precedent - real DnD needs a browser).** The model + pure logic are unit-tested: `card-drag.test.ts` (payload incl. heading + bold tagline + highlighted-only body, non-card/empty → null, **side-scoped heading**, **doc unmutated**, handle rendering, the wire-format round-trip); `card-drop.test.ts` (`snapDropPos` before/after/clamp, `insertSpeechBlocksAt` **observable placement between existing blocks**, `handleSpeechCardDrop` with a **stubbed `view.posAtCoords`** proving the card lands at the resolved position, non-card drag ignored, the `dragover` indicator/`dropEffect`); `card-drag-drop.integration.test.tsx` composes both halves through a shared fake `DataTransfer` and asserts the Auto-Speech copy lands at the drop position **and the source block file is byte-for-byte unchanged**. **jsdom ships no `DataTransfer`** - tests use a tiny stand-in exposing `types`/`get/setData`. The real drag→drop gesture (grip drag, copy cursor, drop indicator, bold tagline landing in the docked speech, source card intact) was **browser-verified in Chrome** via scripted `DragEvent`s carrying a real `DataTransfer`.
