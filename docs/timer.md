# Floating timer widget

## Floating timer widget (`src/timer/`)

The floating Timer widget overlaid on the flow sheet (PRD: Flow Sheet Widgets): two side-coloured prep timers, a dynamic speech timer, all click-to-edit.
It is deliberately **self-contained** - it depends only on the app shell (design tokens) and holds no document/Yjs/IPC coupling; every timer is **component/session state only, nothing persisted** (persisting timer history is explicitly out of scope). Re-exported from `src/timer`.

- **`useCountdown(initialSeconds)` is the shared engine** behind every timer: `{ seconds, running, start, pause, toggle, reset, setSeconds }`. It ticks off a single `setInterval` that exists only while running (a paused timer holds no timer resource), clamps at 0 (auto-pausing there via a pure effect, never counting negative), and `reset` restores `initialSeconds` while `setSeconds` (the click-to-edit commit) changes the live time *without* moving that reset baseline.
- **Gotcha - never nest a state setter inside another setter's updater.** React StrictMode (on in `main.tsx`) double-invokes state updaters in dev, so a `setRunning(...)` called inside a `setSecondsState((s) => {...})` updater fires **twice** and cancels itself out - `toggle`/`start` silently no-op in the real app while unit tests (no StrictMode) still pass. The guard-against-a-spent-clock read that tempted the nesting instead rides a `secondsRef` (kept current each render) so `start`/`toggle` read the latest seconds with a **pure** `setRunning` updater. `useCountdown.test.tsx` has a `renderHook(..., { wrapper: StrictMode })` regression test pinning this; this bug is invisible to non-StrictMode tests, so **browser-verify timer controls** (this was caught via chrome-devtools-axi, not the suite).
- **`formatTime`/`parseTime` (`countdown.ts`, pure)** are the `M:SS` display/parse contract click-to-edit rides; `parseTime` is the inverse of `formatTime` for any value it produces (accepts `M:SS`/`MM:SS` with 0-59 seconds, or bare seconds; returns `null` on unparseable input so the editor keeps the prior value). `DEFAULT_PREP_SECONDS = 180` (the PRD's 3:00); `DEFAULT_SPEECH_SECONDS = 300` is an arbitrary editable starting point (speech lengths vary by format).
- **`EditableTime`** renders the formatted time as a `<button>`; a click swaps it for a text field seeded with the same string. Enter/blur commits via `parseTime`; Escape or an unparseable value discards. Editing is local UI state - it never pauses/resumes the countdown. **aria-label gotcha:** the editable value's label (e.g. `"Aff prep time"`) is a substring of the control labels (`"Play Aff prep timer"`), so tests must query the value button with an **exact** name, not a `/regex/` (a regex matches the play/pause/reset buttons too).
- **`PrepTimer`** (`side: "aff" | "neg"`, a local `TimerSide` type to stay self-contained) is a 3:00 countdown coloured by the aff/neg design tokens (`border-*-strong`, `text-*-strong`, `bg-*-soft`) with play/pause + reset; the section carries `data-side`. **`SpeechTimer`** is one editable countdown whose label is the selected speech: a selector row of speech labels plus a `>` advance button (wraps past the last back to the first). **Selecting or advancing only relabels the running speech - it never touches the countdown**, so switching speeches never interrupts timing (or flowing). **The selector reflects the ROUND's actual speeches, format-agnostically.** `SpeechTimer`/`TimerWidget` take an optional `speeches?: readonly string[]` prop; when non-empty it drives the selector (`RoundScreen` passes the flow's live `useColumns(handle)` labels, so a Public-Forum or any non-Policy round shows `Con Case`/`Pro FF`/… - not the generic Policy set), and it **falls back to `SPEECH_OPTIONS` (`AC`, `NC`, `CX`, `AR`)** when omitted/empty (standalone use, no columns yet). The widget stays self-contained - it takes labels as plain **data**, never a document handle. The held selection is clamped when the list shrinks (a column removed), and the selector row `flex-wrap`s + truncates so many/long labels render cleanly.
- **`TimerWidget`** composes both prep timers + the speech timer inside a `pointer-events-none absolute inset-0` overlay whose card is `pointer-events-auto` - so clicks anywhere outside the card **pass straight through to the flow beneath**, satisfying the PRD's "floats over the flow without blocking flow interactions".
  - **The card is DRAGGABLE, with the drag position persisted (`src/timer/timer-position.ts` + `timer-position-storage.ts` + `useTimerPosition.ts`).** The flow is a full-bleed, *pannable* column grid, so a fixed top-right pin always sits over some column's header + first contention - and on the rightmost column that overlap **hard-blocks clicking into it** (audit divergence D1; it broke `flowContention(4)` in the round-driver). Collapse alone doesn't satisfy the PRD ("without blocking") when *expanded*, so the card floats at a debater-chosen position: grab the "Timers" header (`data-testid="timer-drag-handle"`) and drag it over whitespace (e.g. below the short columns). Position is a **fraction** `{x,y}∈[0,1]` of the card's travel (`timerOffsetPx`/`timerPositionFromPointer` are the pure render/drag math, unit-tested since jsdom measures nothing - the `split-drag` precedent), so it stays sensible across canvas resizes; it persists in `localStorage` (`fulcrum:timer-position`), per-machine view chrome like the dock layout, never in Yjs. The drag handler listens for **pointer** events (Chromium raises them for mouse input, so the harness's real-mouse drag drives it); the collapse toggle `stopPropagation`s its own `pointerdown` so collapsing never starts a drag.
  - **Placement - overlay the canvas, not the whole panel.** `RoundScreen` hands the widget to `FlowSheetPanel`'s optional `overlay` slot (`<FlowSheetPanel handle={...} overlay={<TimerWidget speeches={speeches} />} />`), which renders it inside the **canvas** wrapper (made `relative`) - above the flow columns but **clear of the column-controls strip above and the RFD region below**. It is *not* a sibling of the panel: mounting it over the whole panel pinned it top-right where it fully covered the "Add column" button on a fresh (column-less) round, making the first action unclickable. Keep the timer in the `overlay` slot so it only ever floats over the flow columns.
  - **Collapsible (narrow-viewport reachability).** Because the card is pinned top-right and columns grow *downward*, an expanded card sits over the **first contention of whichever columns it overlaps** - unavoidable for any fixed overlay on a column grid, and acute at narrow widths where columns pack tight (a contention under the card is unclickable). So the card is collapsible: a `data-collapsed` `<section>` with a `Collapse timers`/`Expand timers` toggle (`aria-expanded`) that hides the timers down to a compact "TIMERS" bar, so a debater tucks it away to reach the flow beneath and re-expands to time. Defaults **expanded** (timing is a core need); collapse is session state, so navigating away and back to the round resets it to expanded.
