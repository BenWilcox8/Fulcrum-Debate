# ToC sidebar and ToC bulk-send pipeline

## ToC sidebar (`src/toc/`)

Consumes `observeOutline` + `buildOutlineTree` from `src/editor/headings` - never re-derives outline structure.
`TableOfContents({ editor, scrollContainer?, selection?, toolbar? })` is the always-visible `<nav>`; `TocRow` is one row.
`navigateToHeading(editor, pos)` guards against stale positions (out-of-range or no longer a heading = no-op, not a throw).

- **`selection` + `toolbar` keep `TableOfContents` reusable while adding checkboxes.** The `selection?: TocSelection` prop (from `useTocSelection`) fills each `TocRow`'s reserved `leadingControl` slot with an "include this section" checkbox (`aria-label="Include {text} in speech"`); the `toolbar?: ReactNode` slot renders above the heading list. Both are optional - omit them for a plain read-only outline (the default), so any editor with headings still uses the ToC unchanged. `TocRow`'s `leadingControl` slot is now consumed by this checkbox; do not repurpose it for anything else.
- **`useTocSelection()` (`src/toc/useTocSelection.ts`)** owns the transient checkbox set: `{ selectedPositions, count, isSelected(pos), toggle(pos), clear() }`, keyed by **heading ProseMirror position** (headings have no stable id). **Never persisted** (a reload starts empty, mirroring the flow sheet's send selection); a position is a snapshot valid against the document it was read from, and a stale one simply contributes nothing to a send. `selectedPositions` re-references only on change (stable when `clear()` is a no-op), so consumers can memoise off it.


## ToC bulk-send -> Speech Doc pipeline (`src/blockfile/toc-speech.ts` + `src/screens/BlockFileTocPanel.tsx`)

The **Speech Doc Card Pipelines** PRD, ToC track: a debater ticks the "include this section" checkbox on one or more block-file argument headings in the ToC and clicks **Send to Speech Doc**; every checked section's cards flow, {@link src/speech | Auto Speech}-formatted, onto the *bottom* of the {@link src/speech-doc/active-speech-doc | active speech doc}. It reuses the active-speech-doc contract (PR #83) as the target and the Auto Speech engine (`transformToSpeech`) as the formatter, and is a sibling of the flow-sheet Send Flow pipeline (PR #86). Model re-exported from `src/blockfile`.

- **`sectionSpeechBlocks(editor, checkedPositions, options?)` -> `JSONContent[]` (pure, block-file read-only).** For each checked heading position it gathers that heading's **section** = the heading plus every following sibling in the *same side region* up to the next heading of the **same-or-shallower level** (the `section-ops` boundary contract generalised to any heading level; walking siblings within the heading's own parent means the gather can never cross the `isolating` aff/neg boundary). Overlapping selections (a parent heading and a nested one) de-dup by absolute child position, so each card contributes once. It wraps the collected nodes under a throwaway node - `doc.type.create(null, Fragment.fromArray(items))` (**`create`, never `createChecked`** - skips content-expression validation; the engine only walks structure) - and runs `transformToSpeech`, so the ToC pipeline shares the exact speech shaping (bold tagline, cite, highlighted body flattened, un-highlighted stripped, cards separated, section headers preserved). A checked position that no longer resolves to a heading is skipped, not thrown.
- **`appendBlocksToSpeechBody(speechHandle, blocks, fragment?)` -> count (writes the speech doc only).** Appends block-level document-JSON onto the **end** of the speech doc's `body` fragment through a **short-lived headless editor** (`createEditor` + `editorPreset()`, `insertContentAt(doc.content.size, blocks)`, then `editor.destroy()`) - so the append is an ordinary ProseMirror transaction that flows into the speech doc's `Y.Doc` and persists exactly like a hand-typed edit. This is why the pipeline works even though the target speech doc is usually **not** open in an editor when sending from the block-file screen (the block file and the speech dock are different routes) - it does not require a live editor on the target. A speech doc already open in the split-screen dock converges via Yjs. (Contrast Send Flow, which writes raw `Y.XmlElement` clones because its payload is already Yjs paragraphs; the ToC pipeline's payload is engine JSON, so an editor is the clean JSON->Yjs path.)
- **`sendSectionsToSpeechDoc(blockFileEditor, speechHandle, checkedPositions, options?)` -> `{ sectionCount, blockCount }`** composes both; `sectionCount` counts distinct checked sections that contributed >=1 card. **Non-destructive by construction:** the block file is only read; every write lands in the speech doc's own doc.
- **`BlockFileTocPanel` (`src/screens/`)** is the block-file-specific composition (`BlockFileScreen` renders it in place of a bare `TableOfContents`): owns `useTocSelection`, renders the **Send to Speech Doc** button + `role="status"` line as the ToC `toolbar`, passes `selection` down for the row checkboxes, and runs the pipeline. **No-active-doc / empty-selection = deliberate reversible no-ops, consistent with Send Flow's `SendToSpeechControl`:** button disabled until >=1 heading checked; with no active speech doc the send does nothing and shows "No active speech doc - open or select a speech to send into." with the **selection preserved** so the debater can pick a target (via the dock's active-speech picker) and retry. Reads the `DocumentService` provider-tolerantly (`useContext(DocumentsContext)?.service ?? null`) and the active id via `useActiveSpeechDoc`, so a bare render still paints.
- **Tests:** `src/blockfile/toc-speech.test.ts` is the highest seam (real block-file+card editor + real speech-doc handle over `fake-indexeddb`): checked sections -> formatted append (bold tagline, cite, highlighted-only body, `---` separators, preserved headers), only-checked-sections, **block file unchanged**, **persist across a speech-doc close/reopen**, the nothing-checked no-op, and the stale-position skip; heading positions come from the real `getOutline`. `src/screens/BlockFileTocPanel.test.tsx` drives the panel through the real `DocumentService` (checkbox-per-heading + multi-check, disabled-until-checked, send-appends-and-clears + status, and the no-active affordance with preserved selection). `src/toc/useTocSelection.test.tsx` covers the selection hook.
